# Blueprint architecture for Khoảng Lặng

The project is Blueprint-first on a machine that cannot comfortably build C++. Blueprints are binary assets: git cannot diff them, merges are impossible, and the MCP has no undo. The rules below keep the cost of that low and keep a later C++ migration cheap.

## 1. Put rule logic in one place

All game rules (Try Listening, Seal, source-independence check, Attention transitions) live in ONE module: a Blueprint Function Library or a single Actor Component, for example `BP_KL_ListeningRules`.

- Its functions are pure or nearly pure: inputs in, results out. No references to the HUD, character, widgets, or level actors.
- The character, HUD and GameMode only call into it and react to results (return values or event dispatchers). Never duplicate a rule elsewhere.
- Design function signatures for the general case the spec describes. For example, sealing takes an array of sentences even while G1 only passes one, so sets and partial results can be added without redesign.
- Why: tests exercise one module, a canon change touches one module, and a later C++ port (reparenting the Blueprint to a C++ class) moves only that module.

## 2. Data lives in data, not in graphs

- Clue, recording, and source definitions, Attention thresholds and trigger values are data. A designer or agent must be able to change them without opening a graph.
- The MCP cannot create Blueprint structs or enums, so the row-struct DataTable approach is unavailable. Use one DataAsset per record: a Blueprint class derived from a DataAsset / PrimaryDataAsset, with only primitive fields (Name, Text, Int, Float, Bool). Store the source kind as a Name (`independent`, `related`, `interested`) and validate it in a function.
- Prove that creating such a class and an instance works on a throwaway asset first. If the MCP cannot do it, stop and ask the developer to create the base class by hand.
- The source of truth for story content is `data/story/*.json` (see `kl-story-data`); Unreal assets are generated from it. Do not hand-type story facts into an asset that has no JSON counterpart.

## 3. Keep graphs small and readable

- At most about 30 nodes per function. Split into functions with names that say what they do.
- Put presentation in widgets and gameplay in actors or components; do not mix them.
- Prefer event dispatchers (or Blueprint interfaces) over direct references to a concrete class. Tight coupling makes errors easy to introduce when graphs are generated or edited by script, for example the `BP_KL_HUD` BS_ERROR "not a BP_KL_InvestigationComponent_C, therefore Target must have a connection" recorded in SETUP.md.
- Comment non-obvious node groups.

## 4. Naming and folders

Follow the existing prefixes: `BP_KL_` Blueprints, `WBP_KL_` widgets, `DA_KL_` data assets, `SM_KL_` static meshes, `MI_KL_` / `MI_ART_` material instances, `Lvl_KL_` levels. Everything under `/Game/KhoangLang/`. Asset names are ASCII with no diacritics; Vietnamese appears only in text fields (see `kl-vietnamese-text`).

## 5. The edit loop (every Blueprint change)

1. Confirm the Blueprint is not generated by a script (see section 6). If it is, edit the generator too.
2. Git: commit or tag the current state first (`kl-repo-hygiene`).
3. `read_graph_dsl` and save the text to `Saved/agent_artifacts/graphs/<BP>_<graph>_before.txt`.
4. Make the smallest edit that does the job. Prove an unproven tool on a throwaway Blueprint before using it here.
5. `compile_blueprint`, then read the log for that Blueprint (compile returns no detail).
6. `read_graph_dsl` again and compare with what you intended. If it differs, stop and report.
7. Write or update a plain-text summary in `docs/agent/graphs/<BP>.md`: functions changed, inputs and outputs, data assets touched. This is the "text diff" git cannot give you.
8. Save only after the timestamp check in `kl-unreal-mcp-ops`; commit.

## 6. Generated Blueprints

`Content/Python/KhoangLang/build_*.py` and `tools/g1_*.py` generate Blueprints and levels and are idempotent, so re-running one can erase hand edits. For each Blueprint, know which is the source of truth: the script or the asset. Fix bugs in both. Never re-run a generator over assets that were edited after it last ran; check timestamps or ask.

Known example: `BP_KL_Character:PollKeys` reads the key literal "(" instead of Q/E/Tab/F/Enter/Escape; the generator (`build_20_blueprints.py`) emitted the key as `(KeyName="Q")`. Fixing only the asset would be undone by the next generator run.

## 7. When to propose C++

Only for a concrete requirement Blueprint cannot handle cleanly (performance on a measured hot path, a tool Blueprint cannot express). Say what the requirement is, what you tried, and what it would cost on this machine (Visual Studio is not installed; builds are heavy). Wait for the developer to confirm.
